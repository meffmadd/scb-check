# `metrics/` — extracted facts → measurements

Metric classes own calculations, flat result-field names, and units. Reporting composes their results into reports and handles serialization, comparison, and presentation.

- Subclass `Metric` from `base.py` and implement instance `compute()`. Its parameter specification preserves each metric's narrow extracted-fact inputs; declare result units on the class.
- Return a read-only flat `MetricResult` (`int | float | None`). Keep metadata separate from result values.
- Keep each conceptual metric in its own module. Share erosion arithmetic privately in `_mass.py` and measured-count sum/mean/max arithmetic in `_counts.py`. Concrete metrics still own populations, fields, and units; preserve the union, mass, threshold, and zero-denominator semantics in the [architecture guide](../../../docs/architecture.md#metrics).
- Use extracted facts only: source IO, parser traversal, and analysis orchestration stay outside this package. Keep this package independent of `reporting/`.
- CBO uses retained module facts and owns partner-set construction; all summaries are explicitly partial. When changing its population or resolution fallback, preserve the [CBO contract](../../../docs/architecture.md#coupling-between-objects-cbo) and keep unsupported class diagnostics separate from measured partial zero.
- RFC₁ consumes retained `ProjectIR` member selections and direct possible method bodies; MPC, distinct callers, and DAC consume immutable module facts. When changing populations, dispatch, or type eligibility, read their [canonical counting policies](../../../docs/architecture.md#partial-metric-interpretation). Preserve RFC₁'s one-hop union, MPC's per-site implementation-owner policy, callers' static relation/recursion/module partitions, and DAC's attribute count without argument flattening.
- Module-call dependencies consume retained module facts using only static resolved project calls. When changing edges or availability, read the [module-call policy](../../../docs/architecture.md#module-call-dependencies): physical-file modules, supported initialization, distinct directional neighbors, self exclusion, and known unavailable-target eligibility.
- Keep partial measured zeros distinct from unavailable entities. Summarize measured populations only; return `None` summaries when none are measured. Structured per-entity diagnostics remain separate from flat fields. Project aggregates are analyzer conventions, with no quality thresholds.
- Reporting explicitly composes concrete metrics. The base class is a contract, not a registry or automatic dispatcher.
