# `reporting/` — findings → output

Consumes shared `AnalysisResult` for metric reports and `Flags` for location-level human output. [`score.py`](score.py) explicitly composes metric classes and serializes reports; [`comparison.py`](comparison.py) composes and renders before/after/diff reports. See the [ownership and interface guide](../../../docs/architecture.md#report-comparison-interface) when changing contracts and the [JSON report schema](../../../docs/report-fields.md#check-json-report-fields) for canonical fields.

## Ownership

- `Verbosity`, `Erosion`, `CognitiveErosion`, `Syntax`, `CBO`, `RFC`, `MPC`, `DistinctCallers`, `DAC`, `CIC`, `RIC`, `AfferentCoupling`, `EfferentCoupling`, and `ModuleCallDependencies` live in the sibling [`metrics/`](../metrics/AGENTS.md) package. Their `Metric` base declares the calculation contract; concrete classes own their narrow inputs, calculations, result fields, and units.
- `compute_report(AnalysisResult)` owns explicit group composition. `Report` is a mapping alias, with read-only outer and inner mappings, not a runtime class. Keep units outside nullable numerical values.
- Keep calculations and shared erosion arithmetic in `metrics/`. Complexity extraction stays in tree walking.
- `serialize_report` validates contracts and creates fresh plain outer and inner dictionaries. Keep required-field and finite-value validation at the reporting boundary; reject booleans and nonnumeric/nested results.
- Preserve the fourteen canonical groups in the JSON report schema. RFC₁, MPC, callers, DAC, CIC, RIC, and module-call dependencies expose partial summaries plus measured/unavailable populations; calculations and structured diagnostics stay metric-owned. Keep unavailable summaries nullable through serialization and independent-snapshot subtraction. Read the implementation docstrings linked from the [metric index](../../../docs/metrics.md) when changing counting contracts.
- Build the immutable Ca/Ce category/dependency projection once per snapshot and pass it independently to both metrics. Preserve [the shared policy](../metrics/categories.py), category populations, and nullable partial summaries; neither metric depends on the other.
- Extend explicit composition for real metrics; keep the interface free of registries, dynamic discovery, and unused configuration.

## Scoring invariants

- **Verbosity** is the **union** of clone SLOC lines, ast-grep SLOC lines, and structural rule SLOC lines per file, divided by total SLOC. See [`metrics/verbosity.py`](../metrics/verbosity.py). It is not a sum — lines flagged by multiple sources count once.
- **Erosion** denominator is the cyclomatic mass of **all** function-like symbols; numerator is the mass of symbols with `cyc_complexity > 10`. Symbols with `sloc <= 0` contribute mass 0.
- **Cognitive erosion** uses the same calculation with `cog_complexity > 10` and cognitive mass.
- **Mass** = `complexity * sqrt(sloc)`.
- **`total_loc == 0`** zeroes verbosity and all flagged-LOC counts; **zero total mass** zeroes the corresponding erosion score. Guard both.
- **Report comparison is pure.** `compare_reports(before, after) -> Report` returns read-only signed later-minus-earlier differences. Missing required groups/fields are errors. Only absent dotted per-language syntax fields zero-fill over the sorted language union; explicit `None` on either side propagates, including two null operands. Preserve snapshots.
- **Diff composition accepts analyses.** `compute_diff_report(earlier_analysis, later_analysis)` returns an ordinary dictionary with exactly `before`, `after`, and `diff`, using the standalone `compute_report` for both snapshots. Tree paths are command-owned context; there is no `delta` alias or runtime grouping class.
- **Units stay metric-owned.** Use `score.report_unit` for field units and `formatting.format_measurement` for Python text formatting with fixed fractional precision in terminal comparisons. Render from class-declared units, including dynamic syntax fields, rather than recognizing score names. JSON score differences are fractional absolute differences. Human scores are percentages and score differences are percentage points; counts and masses retain their units. Include zero differences, display unavailable values explicitly, and keep quality-gate judgments out.

## Ordered HTML reports

- `trend.py` accepts aligned named `SnapshotSeries` and shared steps through `build_aligned_trend`; `build_trend` remains the positional single-series convenience. Both use a caller-supplied report loader. Omitted snapshots are gaps; compare only neighboring declared steps within a series. Preserve order and repetitions, load each position once, validate complete reports, and delegate adjacent deltas to `compare_reports`. Keep IO/config/pipeline orchestration in commands.
- Immutable `AlignedTrend` / `Trend` / `TrendSeries` retain shared steps, named aligned sources, raw values, metric-owned units, and full read-only snapshot/comparison data, never analysis IRs or Plotly options. Include every canonical field and the observed language-field union; preserve absent snapshot language counts as gaps, including absent changes when neither adjacent input has that language.
- `plot.py` prepares library-neutral data and plot sections. `templates/report.html.jinja` owns the chart-first page layout and safe JSON embedding via `tojson`; `static/plot.js` alone owns Plotly traces/layouts and escaped hover text. Plot one trace per named series without legends. Keep hover to the series name, input label, plotted measurement with units, and series Kendall τ-b; show full paths once in a collapsed source-directory list, without per-plot tables. Include every metric's values plot regardless of its values, without metric-filter controls or classification. Use native collapsed-by-default `details`/`summary` groups for top-level metric prefixes, preserving report order; the chart adapter redraws plots when a collapsed group reopens.
- Kendall τ-b is HTML-only and follows the [trend-summary policy](../../../docs/cli.md#trend-summaries); change that reference together with the code. Classify each series once (defined τ, flat, or too short) and derive every summary from that. Embed coefficients and summaries as numbers; heading text only renders them. Do not plot adjacent changes; keep `trend.py` differences and numerical report contracts unchanged.
- Load templates/assets from the package independently of cwd. Embed pinned Plotly once for offline use and retain license attribution. Enable Jinja autoescape and `StrictUndefined`; only fixed bundled scripts become trusted markup after script-end-tag escaping. Escape data-derived hover text separately for Plotly's HTML-like formatting.
- Keep raw values separate from percentage display. Preserve null gaps, zero/isolated markers, metric-owned units, and partial-coverage caveats. Explain that charts require JavaScript; source directories remain accessible without it. Keep score formulas and numerical JSON schemas unchanged; extend explicit composition rather than introducing a plotting registry or backend abstraction.

## Rendering

[`render.render_flags`](render.py) emits flags ordered by `(display_path, line, kind_rank)` where `kind_rank` is clone=0, ast-grep=1, structural rule=2, erosion=3, cog_erosion=4. Tests assert on textual markers (e.g. `"duplicate-structure:"`, `"warning[...]"`, `"trivial-wrapper[warning]"`, `"erosion: function ..."`, `"cog_erosion: function ..."`), not the exact layout — preserve those prefixes.

Clones are grouped by `group_hash` so each duplicate group renders once, listing every instance inline under a shared `duplicate-structure:` header (separated by `┆`). Clone line counts and body snippets use duplicated SLOC lines, so docstrings, comments, and blanks inside the clone span are not counted or displayed. Don't reintroduce the "other instances:" cross-reference footer — the inline instances replace it. The group is anchored (for ordering) at the earliest `(display_path, start_line)` instance.
